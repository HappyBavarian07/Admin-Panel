# Admin-Panel 9.0.0 release notes (draft)

Draft for 9.0.0, the release after 8.7.0 (the breaking changes below are why it is a major version). The `pom.xml`
says 9.0.0. Written from the commits and the audit file up to 2026-10-21.

Check before publishing:
- The git tags stop at 8.7.0 (2023-11) and the history before 2026-06 is not in this repository, so this draft only
  covers the work from June 2026 on. If anything changed between 8.7.0 and June 2026, add it from your own notes.
- The Hybrid line below and the "Known limits" list.

---

## Spigot update post

Admin-Panel 9.0.0 moves the plugin onto CoolStuffLib 3.0.0 and fixes a long list of problems that only showed on newer
servers. Tested on Spigot 1.21.10 with Java 21, including a `/reload`.

New
- Warning system: `/warn`, `/warnings`, `/unwarn` and a rebuilt warning menu. Warnings expire by themselves
  (`Warnings.DefaultExpiry`), can escalate to a kick, temp ban or console command at a set count, and stay in the
  database as history. Turn it on with `Pman.Actions.WarningSystem: true`.
- `/disableditems` (alias `/ditems`) is registered and works.
- `/addon disable`, `/addon reload` and `/addon info` have their own permissions.
- Player heads in the menus accept a texture hash, a full URL or a Base64 value.
- Ten new reversible trolls in a "More trolls" menu: creeper hiss, fake explosion, jumpscare, demo screen, safe TNT
  (looks real, no damage), launch, random hop, spin camera, no-jump and slow-motion. Every troll has its own permission
  and a switch in `config.yml`; a stop-all button ends everything.
- Potion menu: effects go to the chosen player, with presets, search, categories, and duration and level by chat prompt.
- Spawning menu: count, baby, custom name, glowing, armor, rider, category filter and search.
- Ban and kick menus: reason and duration presets from `config.yml`, IP ban, silent mode, a confirm step, and a ban
  list that shows who banned, when and how long is left. Bans and kicks are written to the warning history.
- World menus rebuilt: the world list also shows world folders that are not loaded (click to load) and has search, a
  loaded/unloaded filter and an import button. The settings menu adds difficulty, monster and animal spawning, keep
  inventory, set spawn, world border size, the seed, a list of the players in the world, and duplicate, rename and
  delete. Time and weather are one menu with presets, hour steps, a typed time, freeze time and a weather duration.
  The gamerule menu has search, categories, typed values and a reset to the default. World creation has a seed,
  presets (normal, flat, void, amplified, large biomes), difficulty and "teleport after creating".
- Startup in stages: a part that fails to start (Vault, SuperVanish, Bungee/socket sync, the updater, the addon loader,
  bStats, trolls, warnings) no longer takes the plugin down. `/apadmin status` and a new status menu (red torch in the
  start menu when something is broken, also `/openpanel StartupStatusMenu`) list every part with its status and the error
  text. Buttons of a broken feature show "unavailable" with the reason instead of throwing. If something the panel cannot
  run without fails (database, language, commands, permissions manager, PlaceholderAPI) it logs one clear error and
  disables itself instead of staying half started.

Fixed
- Menus that list players, worlds, plugins or languages acted on the wrong entry on page 2 and later.
- Chat input in the plugin install, world create and permission search menus now works.
- The database settings in `database.properties` are read correctly (MySQL keys), `mariadb` works as MySQL.
- Maintenance mode, chat mute and the updater cache survive restarts. The updater trusts its cache for one hour.
- `/openpanel <menu> <player>` needs `AdminPanel.open.other` and no longer matches name prefixes.
- Many smaller command, backup and language bugs, see the GitHub release.

Before you update
- Language files move into folders: `languages/en.yml` becomes `languages/en/...` on the first start. Your edits are
  kept and the old file is saved in `languages/_backup/<date>/`. Nothing is rewritten without a backup.
- `/apadmin report` and its Discord webhook are removed.
- The old `plugin_data.db` is imported once and renamed to `plugin_data.db.imported`.
- `/apadmin reload` asks you to run it a second time within 10 seconds.
- Unbanning from the ban list needs `AdminPanel.PlayerManager.PlayerSettings.Unban` (it was declared but never
  checked). Choosing an IP ban needs the new `...PlayerSettings.BanIp`. A non-silent ban or kick from the menus now
  announces itself in chat.

## GitHub release

### Highlights

- Built on CoolStuffLib 3.0.0 (typed command arguments, declarative menus, merged language storage, JPA tables).
- New warning system with expiry, escalation rules and history.
- The DataService and its second service registry are gone. Runtime data lives in database tables.
- Every command uses the CoolStuffLib 3 command API, and almost every menu uses `MenuAction`.
- Removed the Discord bug report and its hard-coded webhook.

### Breaking changes

- **Startup:** a missing PlaceholderAPI used to disable the plugin and then keep initializing it; it now stops the startup
  cleanly. A language that cannot be loaded does the same. A failing socket data client is reported as a failed stage
  instead of only being logged. New permission `AdminPanel.AdminPanelAdminCommands.Status` for `/apadmin status` and the
  status menu.
- **World menus:** `TimeChangeMenu` and `WeatherChangeMenu` are replaced by `WorldTimeWeatherMenu`. `WorldLoadEvent` is
  no longer fired because the Load button could never be reached (only loaded worlds were listed); loading a world from
  the list fires no event. `WorldCreateEvent` gets a seed (new constructor, `getSeed`, `setSeed`) and `TimeChangeEvent`
  gets `getTicks` for times that are not a preset. New permissions below `AdminPanel.WorldManager`: `Load`, `Unload`,
  `Delete`, `Duplicate`, `Rename`, `Import`, `Teleport` and `Players` (unload and delete had none before). Deleting or
  unloading a world moves its players to the main world instead of kicking them, and the main world cannot be unloaded,
  renamed or deleted. New worlds generate structures by default (the old menu defaulted to off).
- **`GiveEffectToPlayerEvent`** now carries the player who receives the effect. It carried the staff member who
  clicked before, and the potion menu applied the effect to the wrong player.

- **Removed `/apadmin report`** and the API methods `AdminPanelAPI.reportBugToDiscord(...)` (three overloads) and
  `AdminPanelAPI.getCooldownTimeMap()`. The webhook URL was hard-coded in the jar and is removed from the code, but it
  still exists in older releases and in git history, so it should be deleted on Discord.
- **Language files** move into folders on the first start of CoolStuffLib 3 (`languages/<lang>/language.yml`,
  `messages/*.yml`, `items/*.yml`, `titles.yml`). The old single file goes to `languages/_backup/<date>/`. New keys are
  added to the matching file; your lines are never rewritten. If you keep a copy of `en.yml` next to the folder it is
  ignored and reported once per start.
- **DataService removed.** Flags, plugin descriptions and the updater cache are in the tables `plugin_flags`,
  `plugin_descriptions`, `updater_cache` (same database and prefix as the permissions). A `plugin_data.db` in the
  server root is imported once and renamed to `*.imported`.
- **Hybrid server support removed** (`HybridCompatMenu`, `HybridServerUtils`, `InventoryViewWrapper`). Commit of 2026-06-16; drop this line if it already shipped in an earlier release.
- **Permissions:** `/addon enable|disable|reload|info` use `AdminPanel.AddonManageCMD.<Action>`;
  `/openpanel <menu> <player>` needs `AdminPanel.open.other`.
- **`/apadmin reload`** needs a second run within 10 seconds.

### New

- Warning system: `/warn <player> <reason>`, `/warnings <player> [page]`, `/unwarn <player> <number|all>` (console
  allowed) and a warning menu that edits the reason, ends a warning (left, right and shift click) and removes it after a
  confirmation. Warnings live in the table `player_warnings` with status ACTIVE, EXPIRED or REMOVED and are never
  deleted. `warnings.yml` is imported once. Config block `Warnings:` with `DefaultExpiry` and `Escalation` rules
  (KICK, TEMPBAN, COMMAND).
- `/disableditems enable|disable|list` (alias `/ditems`) with item name completion and a working
  `DisabledItemsListener`.
- `/addon list|enable|disable|reload|info`, each with its own permission and messages.
- Head textures can be a hash, a full URL or a Base64 value; player heads keep their full names.
- One `MenuOpenCommand` opens every menu through `/openpanel <menu> [player]`, one `AdminActionCommand` covers the
  reload and update commands.
- The Maven build copies the jar to local test servers only through the profile `copy-to-test-servers`, active when
  `F:\Weitere Minecraft Test Server` exists.

- Trolls: a registry (`trolls/`) so new trolls are one class; ten new ones (see the Spigot post), each with the
  permission `AdminPanel.PlayerManager.PlayerSettings.Actions.Troll.<Id>` and the switch `Pman.Actions.Trolls.<Id>`.
  Time-based trolls stop when the target leaves, on stop-all and on plugin disable. The primed-TNT troll is called
  `SafeTnt` because Bukkit lowercases permission names and `FakeTnt` would collide with the old `FakeTNT`.
- Potion and spawning menus rebuilt (see the Spigot post); spawn count is capped by `Pman.Actions.Spawning.MaxCount`.
- Ban and kick menus: presets in `Pman.Actions.Ban.Presets` and `Pman.Actions.Ban.Durations`, IP ban and silent defaults
  in `config.yml`. Exempt players stay protected. Bans, kicks and warning escalation bans are stored in the warning table
  as status `RECORD`: they never count as active, never trigger escalation, and show with a marker in `/warnings`.
- World menus: the pure parts (`worlds/` package: names, folder scan and copy, gamerule edits, time parsing, create
  presets) are unit-tested; `WorldOperations` holds the Bukkit calls. Copying and deleting world folders runs off the
  main thread; loading, unloading and creating worlds does not. A unit test checks that every language key the world
  menus read exists in `en.yml` and `de.yml` (it found `On`/`Off` item keys, which YAML reads as booleans).
- Startup: `AdminPanelMain.onEnable` is a list of `Startup.run(id, required, action, dependsOn...)` calls (`startup`
  package). A stage that throws is recorded and logged; a required one aborts the startup; a stage can throw
  `Startup.DisabledException` when it is off on purpose (config switch, plugin not installed), which is not a failure. The
  code of the stages stays in the old methods.
- `AttributeLookup` finds attributes by name at runtime, so the heal button works with both the old and the new attribute
  names.

### Fixed

- **Language files:** English had no Staff Chat texts and German lacked the whole Data Client menu and its chat texts; both
  languages have the same keys now (a unit test checks it). The auto updater menu and the permission info used message keys
  that did not exist, and the permission info showed the description only when it was empty and failed for an offline target.
- **Plugin install menu:** it said "successfully installed" after a failed download and reset the file name to `null`.
- **Newer servers:** tested on Spigot 1.21.1, 1.21.5, 1.21.10, 1.21.11, 26.1.2, 26.2 and 26.3 (fresh install, console commands,
  reload, stop). `GameRule` (an interface from 1.21.11 on) and `Sound` (an interface from 1.21.3 on) are looked up by name
  instead of through their enum/class methods, which threw `IncompatibleClassChangeError` there: the gamerule menu and the
  open sound of the start menu. Gamerule groups in the menu come from words in the rule name, so renamed rules still land in
  a group.
- **Chat input in menus:** ten menus (money, plugin install helpers, auto updater, plugin description, load plugin by
  name, chat manager, server broadcast, whitelist, data client settings, language migration edit) waited for the next chat
  message in a menu that implements a listener; the menu system unregisters those when the inventory closes, so the typed
  text went to public chat. They use the chat prompt now. Maintenance mode (login, server list) and the global chat mute
  moved to permanent listeners (`MaintenanceListener`, `ChatMuteListener`), disabled plugin commands to
  `DisabledCommandsListener`; before they only worked while the menu was open.
- **Trolls:** the old trolls (hurting water, block prevent, villager sounds, dupe mobs, chat mute, freeze) were enforced by
  listeners inside the troll menu and stopped working when it closed. All trolls are now in the registry and in one
  paginated menu; the old fake TNT is replaced by safe TNT, and the per-troll events of the old menu (`PlayerChatMuteEvent`,
  `BlockBreakPreventEvent` and so on) are no longer fired, `TrollToggleEvent` covers every troll. The old trolls keep their
  permissions, item texts and saved state.
- **Menus:** a button that goes to a parent menu shows a back arrow instead of the close barrier; paginated menus have one
  back arrow in the middle instead of two close buttons. Money menu rewritten (Vault), messages show amount and balance.
  Ban screen has real line breaks and no raw placeholders (new key `TargetBanMessage`, old texts in existing language files
  are not rewritten). Plugin command and permission lists use the language file (colors and placeholders were raw).
  The command settings menu returned to itself instead of the plugin settings.
- **World menus:** animal spawning is switched through the spawn limit (`setSpawnFlags` ignores animals); the time and
  weather menu says when a world did not take the change (nether and end use the overworld time and weather).
- **Spawning menu:** the entity list threw `IllegalStateException` for the unknown entity type on current servers and
  would have kept the menu from opening.
- **Fresh install:** the staff chat started before the language manager, which aborted the first start; the log folder of
  the dependency loader was not created (stack trace in the log); `/apadmin backup listBackups` threw when no backup existed.
- **Gamerule menu:** every click threw a `ClassCastException`.
- **World list:** a click on page 2 opened the wrong world; unloaded worlds could not be loaded at all.
- **World save and load** built paths with backslashes (Windows only), created `raids.dat` as a folder and swallowed the
  errors; all of that is gone and errors go to the plugin log.
- **Time menu:** every button looked up its slot under the sunrise key.
- **Potion menu:** effects were checked, added and removed on the clicker instead of the target, and the clicked effect
  came from the page-relative slot.
- **Menus:** list menus (banned players, whitelisted players, plugin commands and permissions, languages, spawning,
  game rules) use the clicked entry; before, the page-relative slot indexed the whole list, so page 2 and later acted
  on the wrong entry. `PermissionListMenu` no longer matches items with `isSimilar`. The chat input of plugin install,
  world create and the permission search works: those menus were `Listener`s whose handlers CoolStuffLib unregisters when
  the inventory closes.
- **Database:** `database.properties` is parsed by `DatabaseSettings` (MySQL keys, defaults, port check, relative SQLite
  path). `dbtype=mariadb` was refused by CoolStuffLib and is an alias for MySQL now.
- **Persistence:** maintenance and chat-mute flags were read from `data.yml` before it was loaded and are now stored in
  a table. Per-player languages were stored twice and are only kept by CoolStuffLib's handler.
- **Updater:** one cache key set was shared by every plugin and never expired; the cache is per resource id and trusted
  for one hour. `AutoUpdaterManager` kept a second copy of `data.yml` and overwrote other data when saving.
- **Commands:** `/openpanel` crashed on CoolStuffLib 3; `/openpanel <menu> <name>` matched name prefixes;
  `/apadmin backup` threw NullPointerExceptions for unknown backups; `/perplayerlang` never sent its usage and its
  target check was wrong; the German addon messages sat outside `Messages`; `/addon info` read a key that does not exist.
- **Startup:** a failing on-load addon is logged and skipped instead of stopping the load; bungee and data client shut
  down null-safe; the start-up logger is created in `onLoad`; CoolStuffLib is shut down on disable; the start menu hint
  item was missing from the language file.
- **Logging:** about 85 `printStackTrace` and `System.out` calls now go to the plugin log file.
- **Threads:** permission setup, the addon loader and the auto updater run as Bukkit async tasks; the permission setup no
  longer waits forever on a database that never starts.

### Internal

- Search: the spawning, potion and gamerule menus use CoolStuffLib's `PaginatedMenu.setSearchable` instead of three copies of
  the same chat search, and the plugin, player, banned, whitelist, command, permission and auto updater lists have a search
  button too (left click: type a word in chat, right click: clear).
- The texts of the auto updater and of the permission menu searches come from the language files.
- AdminPanel uses CoolStuffLib's config updater and `ChatUtils`; the copies (`ConfigUpdater`, `OldConfigUpdater`,
  `AdminPanelUtils` formatting, the unused `ChatUtil`) and four unused classes (config reload menu, the unfinished language
  migrator menus, `PlayerPermissions`) are gone.
- Unit tests: 132 (warnings, sanctions, durations, trolls, importer, menu commands, addon names, world logic, startup
  stages, language keys of the world menus and the startup status). A server smoke test
  (`tools/run-adminpanel-smoke.sh`) starts Spigot 1.21.10, runs the console commands, reloads and fails on missing
  language keys.
- The jar minimizer keeps CoolStuffLib and classgraph whole; the unused `log4j-core` dependency is gone.

### Known limits

- Clicks in the migrated menus and the visual effects of the new trolls were checked by the unit and smoke tests but not
  yet by hand on a server (jumpscare, demo screen, safe TNT, spin camera, potion and spawning options, the ban list).
- The unavailable buttons are in place for the money, warning, more-trolls and auto-updater entries; the data client
  menus and commands keep their own "not enabled" message. Retrying a failed stage needs a restart.
- The world menus were checked by the unit tests and by compiling, not by hand on a server (create with the void preset,
  duplicate, rename, import, delete, the time and weather screen, the gamerule clicks).
- Creating a world generates its spawn area on the main thread, so the server pauses while it runs.
- The void preset uses a flat world generator with one air layer; servers older than 1.16 may ignore the setting.
- The no-jump troll only works on servers with the jump strength attribute (1.20.5 and newer).
- The spin camera teleports every tick for 5 seconds; anti-cheat plugins may react.
- BungeeCord and socket sync is still marked under development.
- `PluginInstallMenu` resets its file name after Install; reopening the menu from the same instance fails.

### Upgrading

Back up the plugin folder, replace the jar and start the server once. Read the console for the language migration lines
("Moved en.yml into the folder en/"). Requires PlaceholderAPI. Optional: Vault, SuperVanish.
